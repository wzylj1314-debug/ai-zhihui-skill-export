# 知识沉淀判断规则

本文件给 `zhihui-knowledge-capture-decision` 使用。任意 Agent 可按这里判断内容是否应该成为可复用知识。

## 一、核心目标

不要“看到内容就入库”。先判断：

- 是否可复用。
- 是否高频或有代表性。
- 是否已经存在相似内容。
- 是否涉及敏感信息。
- 是否会形成错误承诺。
- 应归入哪类知识。
- 是否需要人工复核。

## 二、入库决策

| 决策 | 判断标准 |
|---|---|
| 入库 | 内容清晰、可复用、非敏感、不重复，能帮助后续 Agent 稳定回答或判断 |
| 暂存 | 可能有价值，但样本不足、表达不完整、需要补充证据 |
| 不入库 | 低频噪声、一次性问题、已被覆盖、无业务价值、太模糊 |
| 转人工复核 | 涉及价格、合同、版权、退款、API、隐私、投诉、产品承诺或不确定能力 |

## 三、知识类型

| 类型 | 适用内容 |
|---|---|
| FAQ | 高频标准问答 |
| 真实问法 | 客户原始表达、口语化问法、容易触发意图识别的表达 |
| 排障规则 | 失败现象、可能原因、处理步骤、升级条件 |
| 风险边界 | 商务、合同、版权、退款、API、隐私、投诉、法务承诺 |
| 销售话术 | 价值表达、场景说明、跟进话术、套餐边界 |
| 产品反馈 | 功能缺口、体验问题、批量需求、集成需求、效果稳定性 |

## 四、敏感信息

必须移除或转人工复核：

- 手机号、微信、邮箱、账号、订单号。
- token、webhook、API key、密钥。
- 合同原文、报价单、付款信息。
- 客户公司内部信息。
- 原始截图中的隐私内容。
- 未确认的版权、退款、价格和法务结论。

## 五、去重规则

判断重复时关注：

- 问题是否已经有 FAQ。
- 真实问法是否只是已有问法的轻微改写。
- 排障规则是否已有同类失败现象和处理步骤。
- 风险边界是否已有同类限制。
- 产品反馈是否已有相同功能缺口。

重复内容不直接入库。可以：

- 不入库。
- 补充为已有条目的新问法。
- 暂存等待人工合并。

## 六、草稿规则

只有在内容可复用且安全时才生成草稿。

草稿要求：

- 不含客户隐私。
- 不含未经确认的承诺。
- 表达简洁。
- 能被后续 Agent 直接引用。
- 明确归属到目标 Reference。

## 七、混合场景

| 场景 | 处理方式 |
|---|---|
| OCR 里既有 FAQ 又有手机号 | 标记敏感，草稿中移除手机号，必要时人工复核 |
| 会话里有产品反馈和投诉 | 产品反馈可暂存，投诉风险必须人工复核 |
| FAQ 草稿包含价格承诺 | 转人工复核，不直接入库 |
| 客户问法很口语化但很常见 | 可入 `真实问法`，必要时补 FAQ |
| 内容只是一次性操作记录 | 不入库 |
