# 业务信号判断规则

本文件给 `zhihui-business-signal-extraction` 使用。其他 Agent 只需要按这里的规则判断客户沟通中的业务价值。

## 一、核心目标

不要只总结聊天内容，而是从客户原话里提取可行动业务信号：

- 是否值得销售跟进。
- 客户真实痛点是什么。
- 是否有预算、周期、决策链。
- 是否出现产品反馈或功能机会。
- 是否有风险、投诉或敏感承诺。
- 下一步应该由谁处理。

## 二、商机等级

| 等级 | 判断标准 | 示例线索 |
|---|---|---|
| A | 明确需求 + 明确跟进动作，并且预算、周期、决策链、团队规模中至少命中一项 | “价格怎么算”“这周要看方案”“老板想看”“整个团队都要用” |
| B | 有明确需求，但采购信号、时间窗口或决策链不完整 | “我们想试一下”“这个功能挺适合我们”“能不能先看看效果” |
| C | 只有兴趣或泛泛咨询，缺少明确紧迫性和跟进路径 | “我了解一下”“先看看”“之后有需要再说” |
| None | 无业务价值、纯售后问题、无效线索或噪声 | “怎么登录”“图生成失败了”“刚才发错了” |

## 三、信号类型

| 信号 | 要识别什么 | 输出字段 |
|---|---|---|
| 客户痛点 | 效率、成本、上新速度、打样、素材生产、团队协作、流程接入 | `pain_points` |
| 预算信号 | 价格、套餐、试用、采购、审批、付款、成本 | `budget_signal` |
| 周期信号 | 今天、本周、本月、上新节点、提案节点、长期观察 | `timeline_signal` |
| 决策链 | 老板、设计主管、采购、IT、运营、使用者、财务 | `decision_chain` |
| 产品反馈 | 功能缺口、效果不稳、批量需求、集成需求、体验问题 | `product_feedback` |
| 风险信号 | 退款、合同、版权、隐私、投诉、承诺风险、法务问题 | `risk_flags` |
| 下一步动作 | 销售跟进、产品评估、技术支持、客服处理、暂不处理 | `next_actions` |

## 四、判断原则

- 只根据客户表达和上下文判断，不凭空脑补。
- 每个关键判断都要有证据，优先引用客户原话。
- 弱信号可以标记为 `隐含` 或 `不明确`，不要强行判成明确。
- 售后问题如果没有购买、团队、预算、周期或产品机会，不要硬判成商机。
- 风险和投诉不能被业务摘要吞掉，必须单独放进 `risk_flags`。

## 五、常见混合场景

| 场景 | 处理方式 |
|---|---|
| 客户一边问价格，一边说团队想试 | 可能是 A 或 B，取决于是否有明确跟进动作、周期或决策链 |
| 客户反馈功能不好用，但提到“如果稳定就全团队用” | 同时记录产品反馈和商机信号 |
| 客户只是问功能怎么操作 | 通常是客服问题，商机等级 `None` |
| 客户提出退款、版权、合同、隐私 | 标记风险，下一步给客服或人工处理 |
| 客户说“老板想看” | 记录决策链信号，可能提高商机等级 |

## 六、负责人建议

| 情况 | owner |
|---|---|
| 明确试用、报价、演示、购买意向 | `销售` |
| 功能缺口、批量能力、集成需求、效果稳定性反馈 | `产品` |
| 接入、API、报错、部署、技术排查 | `技术` |
| 投诉、退款、账号、版权、合同、隐私 | `客服` |
| 没有业务价值或信息不足 | `暂不处理` |
